# PR #19 review — 2026-08-29

## Scope

- PR: `dependabot/github_actions/github-actions-14539f6179`
- Original change: `taiki-e/install-action` v2.86.6 to v2.86.8
- Reviewed with the pre-existing mutation-script and changelog work in the checkout because
  the release must contain one coherent, verified state.

## Verdict before remediation

Request changes. The action update itself was authentic and immutable, but the combined tree
was not publishable:

1. The workflow policy test still asserted the v2.86.6 pin, so hosted CI failed.
2. `chacha20` 0.10.1 was yanked, so `cargo audit --deny warnings` failed on main.
3. The published package included `tests/ci_workflow_policy_test.rs` while excluding all seven
   files loaded by its `include_str!` expressions. A fresh package test therefore failed to
   compile.
4. `mutants-run.sh` used one shared scratch directory and broad cleanup, allowing concurrent
   runs to delete one another's live cargo-mutants trees.
5. `mutants-remote.sh` synchronized and mirrored outside its remote lock, allowing concurrent
   invocations to mutate a running checkout or return another run's diagnostics.
6. Remote scratch overrides were not forwarded, mirror failures were suppressed, and stale
   comments described cargo-mutants copy behavior inaccurately.
7. `mutants-staged.sh` reused one fixed diff path, so concurrent hooks could overwrite it.

## Remediation included in the release

- Advanced the verified immutable action pin to current v2.87.1 and updated its policy guard.
- Refreshed the Rust-1.85-compatible lockfile, including non-yanked `chacha20` 0.10.2.
- Excluded the repository-only workflow-policy integration test from published crate sources
  and added a manifest regression assertion.
- Gave every local scratch run, staged diff, remote checkout and mirrored result set a unique
  owned path; cleanup now targets only that owned path and preserves the original exit status.
- Made mirror failure explicit and retained the exact remote run for recovery.
- Added behavioral shell regressions for failure status, stale cleanup, concurrent local runs,
  unique remote runs, scratch forwarding, mirror failure and staged-diff cleanup.
